## B. Shared vs. consumer-owned vs. optional feature boundaries

| Feature | Shared Kit contract | Consumer-specific state/capability (do not override) | Current source-check status |
|---|---|---|---|
| Header/footer/hamburger/sidebar | Optional regions and nav interaction patterns; no forced labels or mandatory display | Existing tarot/frequency/lyric headers, Gomoku/game overlays, chat viewer interface | Existing headers **observed** in 4 inspected HTML/JS entrypoints; whether each page needs shared chrome is **conditional** |
| Breadcrumb and route metadata | Typed route/nav hierarchy, render adapters for path/history/hash and custom breadcrumbs | Each site's native route/location and Pages `base` | **Potential shared feature**; path/routing semantics require fixture tests |
| Dark/light/system | Theme token scopes + preference state and accessible controls | Per-site app palette, text and canvas visuals, game/audio chart meaning | **Conditional**. Existing source has own style; no global CSS injection |
| Shortcuts | Action registry + scoped recording/conflict UI with pointer alternatives | Piano note triggering, game controls, reader/editor bindings | **High conflict risk**; no globally registered default key combos on consumers |
| General Help/About/Privacy/Terms/404 | Templates/route/link governance; enabled individually | Truthful policy text, contacts, what data site processes | Template is shared; legal accuracy remains site-owned; no automatic legal claims |
| Search/i18n/SEO | Optional adapters/metadata generator | Site data/index, dynamic vs static build, language content | **Opt-in**; no global runtime search request or telemetry |
| Visual editing | Only an optional capability-scoped bridge | `kinotch-editor-platform` owns visual editing; legacy/editor integrations already installed elsewhere | **Out of core dependency graph** |
| API/auth/deployment | No secret or session handling; adapters for site metadata only | Tarot Cloudflare worker; each Pages pipeline; `kinotch-identity` | **Out of Site Kit core** |

## C. Representative PoC fixtures and verification order
1. **Vanilla fixture:** static `index.html` + ESM module + a local policy-neutral Help page + modal/navigation themes. Simulate `tarot-draw`/ `line-style-viewer` host behavior **without copying production UI source or private user data**.
2. **React fixture:** Vite + React 19 + a custom keyboard/game control region with framework-owned state and mount/unmount. Simulate `microtone-piano`/ `Gomoku-5D` host interactions without moving React-owned DOM. Include a test binding used for game/piano that must never be consumed by shell shortcuts.
3. Compare same `SiteDefinition` options (immersive vs content, basePath, header slots, theme scope) across both hosts. No consumer migration during M0.
4. Baseline measurement needed: first paint, loaded KB per feature, listener counts after unmount, keyboard focus route, scroll/selection retention, mobile Safari viewport/safe area, third-party network.
5. **Still UNVERIFIED:** deployed-site screenshots and live workflows, physical iPhone, performance budgets and actual Web Awesome/TanStack integration (see M0.2). Static source review is not observational UX proof.

## D. Risk ranking and decisions
- **P0 navigation/keyboard collision:** piano/game dedicated keys and editor shortcuts. Default global hotkeys OFF; scoped capability registration with explicit host actions.
- **P0 style ownership:** content CSS resets could break chat/audio/game. Use Shadow DOM/adapters/scoped CSS where validated; never hard-set app body or `:root`.
- **P0 release boundary:** every inspected Pages deployment workflow publishes on main; **none of these consumers may be changed as part of a Site Kit M0 source audit**.
- **P1 route/basePath divergence:** Vite `./`, `/Gomoku-5D/`, vanilla `./`; consistent URL generation cannot be hardcoded.
- **P1 dependency weight/browser compatibility:** old devices, real-time audio and optional editor loads require per-host measurements.
- **P1 policy/text ownership:** Cloudflare Worker, local settings and audio content demand truthful site-specific handling; generic legal text must not assert safety/compliance.
